# 富贵村财务管理助手：场景化前端重构计划

状态：首期正式界面已实现，进入体验审阅；实施记录见第 12 节。工作分支：`1116_lhq`。

## 1. 核心决定

以 **Story 为首页主入口，District 为财务关系的空间表达，AI 为贯穿阅读和操作的助手**。视频保持固定视角；左侧空地优先承载 Story 阅读区，建筑与资金关系由独立交互层响应。完整聊天默认收起，随时可展开；用户也可以直接进入任意建筑，不设置必须依次完成的流程。

Story 从用户真实财务活动出发，连贯解释本月状况、资金来源与去向、留下的部分、值得关注的变化和下一步选择。每段结论与关键数字都能定位来源、影响场景并进入具体操作；不是把原指标卡改写成几段文字，也不是要求看完故事才能使用功能。原来的多张指标卡、分类饼图、预测卡和长表格分别进入对应建筑，以明确的阅读任务重新编排。数据操作、筛选、图表下钻、家庭权限和历史记录都保留。

四座建筑：

| 建筑 | 用户任务 | 核心内容 | 主视觉与操作形式 |
| --- | --- | --- | --- |
| 商会大厅 · 盘点与规划 | 回顾本月、安排预算与目标、处理共同事项 | Story 回顾、已有预算/目标/家庭议事；可选的本次补充说明 | 组织事实与决策的工作文档；首期不依赖新增月度档案服务 |
| 账房 · 收支账本 | 看清钱的来去，核对和维护流水 | 收支、分类、交易、导入、分类审核 | 一张主图配一份可展开的账册；支持筛选与来源追溯 |
| 钱庄 · 账户与财富 | 了解现在拥有与承担什么 | 账户快照、资产、负债、净资产、覆盖与估值日期 | 资产负债对照及账户清单，突出数据覆盖边界 |
| 集市 · 消费与模拟 | 理解消费去向，比较一次计划的影响 | Story 消费节点、模拟条件、前后差异、预测区间、周期账单、保存方案 | 场景中代表消费发生处；深入后以方案与时间轴比较选择 |

“富贵村”是产品空间隐喻。金额、日期、图表和表单保持现代工具的精确性。使用可读的正式功能名，不把删除叫作“销毁契约”，不要求用户学习游戏规则，也不加入积分、打卡或消费惩罚机制。

建筑原型与业务关联：商会大厅是商贸小镇共同盘点、议事与规划的公共场所；账房保存并核对流水，是证据索引；钱庄承接资金保管、账户与资产负债；集市承接消费发生与未来交易选择。集市可表示消费，明细维护仍归账房，避免两个地点重复做同一套账册。道路、河流只是表达关系的路径，不是额外的真实账户。现有视频建筑外形沿用，只调整命名和交互语义。

## 3. 村庄主页：完整构图与导航

### 3.1 Story、District 与 AI 的层级

1. **景观层**：静音视频与静态封面，固定机位，呈现统一村庄。
2. **财务可视化与空间入口层**：独立 SVG/Canvas 绘制有数据依据的资金关系、章节高亮与局部标签；建筑按钮通过 DOM 提供语义、键盘焦点和业务跳转。
3. **阅读与工作层**：Story 是默认主内容；AI 为就近追问入口与按需展开的会话；进入建筑后呈现具体工作空间。账户、个人/家庭切换和暂停始终可达。

顶部只保留品牌、空间选择、通知与账户；建筑入口旁标注“商会大厅 / 月度盘点”等功能说明。提供“地点”菜单作为与建筑点击等价的导航，兼顾首次用户、键盘与小屏。

视频不是交互引擎。建筑点击、标签、焦点框都用 DOM/SVG 透明区域实现，用户不用精确点击屋门。默认保持场景安静，仅在当前叙事或用户选择相关时显示有限的数据标签；状态数来自真实业务。标签和资金线都属于同一份 Story 数据范围，不能成为另一套互不一致的统计。

### 3.1.1 叙事组织与首期数据边界

首页提供一个连贯阅读面，而非六张横向卡片或六步向导。建议以“概况 → 来源 → 去向 → 结余 → 洞察 → 选择”为阅读骨架，根据数据合并、缩短或省略段落；可通过轻量目录、点选场景、点击数字和直接提问自由跳转。不能完成一段才解锁下一段，也不自动滚屏或自动换章。

| 叙事问题 | 现有能力优先提供的内容 | 场景反馈与行动 |
| --- | --- | --- |
| 本月整体如何 | 收入、净支出、预算执行；一个可核对的结论与少量关键数字 | 商会大厅轻量强调；进入回顾/预算 |
| 收入从哪里来 | 已有收入总额；仅在现有接口覆盖可靠来源构成时细分 | 资金流入钱庄的概念节点；未知来源明确标示，不把收款商户名称直接断言为工资等收入性质 |
| 资金去了哪里 | 全量分类净支出、主要消费类别；账户分配只在有账户归属时展示 | 集市高亮并显示少量类别；点击类别进入账房相关交易 |
| 最后留下什么 | 同期收入减净支出的“本月收支结余”，明确退款、转账和覆盖口径 | 钱庄强调；可进一步核对真实账户快照，但不称作总余额或净资产 |
| 有什么值得关注 | 复用 Agent 已有变化规则、证据与 AI 解释，缺比较基线时不编造趋势 | 相关地点与来源范围联动；查看证据或追问 |
| 下一步做什么 | 根据当前事实提供查账、检查预算、模拟方案等少量相关行动 | 明确目的地与参数；可直接进入，不强制阅读完 |

首期每条 Story 事实绑定月份、个人/家庭范围、口径、数据版本与可下钻目标。数据不足时说清楚缺什么，允许故事简短；收入来源、账户流向或历史对比缺接口时，先展示可信总量或已具备维度，不用客户端分页、模型猜测或无依据的动画补齐。确实影响理解的汇总缺口再评估最小服务扩展，复用共享计算，不创建第二本账。

“收支结余”不必等于账户快照之差：还可能存在历史资金、借贷、估值变动与数据缺口；只有范围与时点可对齐时才做对账解释。账户内部转账不增加收入或消费，也不改变总财富；退款与对应净支出关系单独标明。负结余、无收入、只有转账与跨月退款均需有诚实叙述。

### 3.1.2 动态财务可视化层

首期优先使用 SVG 路径与有限节点，便于和建筑坐标、命中区域及可访问文本保持一致；只有粒子数量或性能实测确有需要时再使用 Canvas。复用已安装的 Motion，不以增加技术栈为目标。

- **读到哪里，场景回应哪里**：当前可见段落或显式选择驱动相关建筑描边、柔和遮罩、入口状态与局部标签。滚动只改变关注范围，不打开建筑、不发请求。允许锁定所选类别；鼠标悬停结束后恢复原章节，避免闪烁。
- **资金关系**：收入流入钱庄、净消费流向集市，可借道路/河流走向绘制路径。账房是记录索引、商会大厅是盘点与决策，不为了四座建筑都动起来而制造额外资金流。
- **诚实的粒度**：无法确定交易账户时，只表达“已记录收入/消费”的汇总关系，标注为概念节点，不呈现具体账户间转账。已知内部转账与消费使用不同线型、箭头和文字，不能仅靠颜色，也不能重复计入收支。
- **金额编码**：同一范围内可用一致比例线宽或静态宽带表达金额，粒子仅表示方向、不代表逐枚金币或精确金额。退款、负值、零额、未知额不使用绝对值冒充消费流；可读数字和说明始终是权威表达。
- **按需展开**：默认只显示当前关系与少量标签；选中节点再看构成，不把完整 Sankey 图覆盖在视频上。每条路径应能解释其范围与来源，无法解释就不绘制。
- **状态一致**：建筑状态、Story 数字与图表共享查询结果/版本；刷新时标示更新，不用旧路径配新金额。钱庄覆盖不足、账房有待确认、集市尚无方案，各有真实空态，不以“灯亮/繁荣”暗示未计算的财富状态。
- **可降级**：暂停、减少动态效果或低性能时保留静态线、箭头、选中状态和文字关系；路径层默认不拦截输入，交互节点单独提供可聚焦按钮。场景中同一关系也能从 Story 的文字/表格理解。

完整视频不能被局部真实重打光；建筑高亮使用校准后的独立 SVG 多边形与低强度轮廓，不追求伪 3D 光照或修改镜头。路径形态、标签密度和强度由视觉原型决定。

### 3.2 布局与热区基准

以视频本身 1920×1080 为坐标系。初步定位（需在实现时通过实际视频帧校准多边形）：

| 地点 | 归一化锚点约值 `(x,y)` | 位置识别 |
| --- | --- | --- |
| 账房 | `(0.51, 0.32)` | 村庄左侧的大型橘色屋顶建筑 |
| 商会大厅 | `(0.84, 0.14)` | 高处、阶梯上方的庄重建筑 |
| 钱庄 | `(0.88, 0.43)` | 右侧有金币与天平的建筑 |
| 集市 | `(0.66, 0.77)` | 下方摊位建筑群 |

以上是标签锚点，不是重叠的矩形点击范围。每个建筑需单独多边形；字幕、AI 容器和弹层覆盖区域优先接收点击。不能让点击聊天输入区穿透到建筑。

Story 阅读区和按需展开的 AI 面板以屏幕阅读尺寸约束宽高；建筑热区、关系路径与场景标签以同一视频坐标映射。不能把整套界面按背景图片比例缩放，导致小屏字体失读。

桌面先验证 1920×1080、1440×900、1366×768。背景可以 `cover`，但热区必须使用同一组变换：`s=max(viewW/1920,viewH/1080)`，`offset=((viewW-1920*s)/2,(viewH-1080*s)/2)`。焦点、标签与建筑统一使用这个映射。某建筑被裁出可视区时，在地点菜单继续保留可达入口，不将不可见的热点留在画面中。

宽屏优先利用左侧约 3%–34% 的空地展示可连续阅读的 Story；宽度先在 380–480px 范围验证。保持一处主要阅读焦点，轻量章节定位和就近“追问”随内容出现。AI 展开可暂时替换这一区域或打开侧栏，关闭后恢复阅读位置与所选对象；具体采用哪种布局交由视觉原型比较，不默认让完整聊天与故事并排争抢空间。长文/长对话的滚动区与操作区分离，200% 缩放时自动进入紧凑布局。

### 3.3 手机与窄窗口

- 小于约 1100px 或建筑被严重裁切时进入紧凑布局：上部村庄场景、下部 Story 阅读面与可展开助手，提供四个地点入口。
- 竖屏阅读优先，不要求同时展示全幅建筑、全文与完整聊天；章节选择可更新顶部场景或静态标记，不能要求反复上下滑动才能理解文字对应哪座建筑。
- 键盘唤起时固定输入区不能被遮挡；使用动态视口、底部安全区，并验证长消息滚动。
- 手机默认静态封面，用户可以主动播放；桌面使用静音循环。低性能与减少动态效果模式均优先静态封面。

### 3.4 主页各状态

| 状态 | 展示与行为 |
| --- | --- |
| 已有账本、已连接 AI | 首先呈现有依据的 Story；按已有授权与频次规则复用/更新洞察，随时展开追问 |
| 没有账本 | Story 明确资料不足，提供账房添加/导入与直接提问入口，不填充假故事 |
| 无 DeepSeek 连接 | 事实 Story 与建筑继续可用；AI 解释区域提示设置入口，本地规则与模拟保留 |
| 发送中 | 发送变停止；可见连接/思考/回复状态；禁止重复提交 |
| AI 失败 | 事实 Story 与规则依据继续显示，AI 洞察局部可重试；主动请求与聊天错误分开，聊天保留草稿 |
| 已有提醒 | 洞察段与通知使用同一提醒事实及去重规则；不因重复进入章节再弹一次 |
| 视频失败 | 静态封面与所有 DOM 功能继续工作 |

## 4. 建筑工作空间：从控制台转为任务界面

点击建筑后，标签回应焦点，工作空间从对应方向展开。视频留作边缘背景并降低亮度或暂停，正文使用不透明或接近不透明的暖白阅读底色。图表不直接压在复杂建筑上。

工作空间拥有统一的标题栏：建筑名、当前任务、返回 Story/村庄。它是路由内容区域，不是层层套叠的弹窗。桌面可先验证占右侧约 62%–75%，数据密集的账房允许展开。AI 按需展开，不默认挤占工作区。进入与退出时保留 Story 阅读位置、月份、范围和当前选中记录，避免每次回到开篇。

### 4.1 商会大厅：盘点与规划

商会大厅承接从 Story 到决定的整理工作：查看选定月份事实、检查已有预算、进入目标和共同事项。首页故事负责帮助理解，大厅负责核对与安排。采用文档/计划工作区，与即时聊天在结构和主操作上区分；不能成为首页 Story 的重复全文或另一套 Dashboard。

首期复用现有汇总与设置：事实可下钻、预算可调整、已有家庭目标/议事可进入。个人目标在当前无独立模型时只作为本次规划输入，不冒充已持久化目标。可选“补充本次背景”使用现有聊天输入送入当前会话，并明确会话保存范围，不新造后台保存接口。无补充也能完成 Story 与业务操作。

#### 后续可选：月度案卷持久化

只有当原型验证用户需要跨会话维护月度缘由，而现有聊天历史确实不足时，再实现 `MonthlyReview`。它不是 Story 上线、首次导入或 AI 使用的前置条件，不在首阶段增加表、发布工作流与独立授权。

若进入此后续阶段，保留原方案中的必要约束：事实摘要与可选缘由/未来约束分栏；用户自述金额不覆盖账本；快照更新进入钱庄；草稿与已保存状态清楚；账本变化不悄悄改写已经确认的说明。按 `owner_id + month` 隔离、并发版本检查、有效期、编辑/删除与请求引用版本必须完整设计。

此时才确定 `MonthlyReview` 模型与读取/保存/删除契约、是否确需单独确认动作，并执行迁移与客户端生成；本计划不预先锁定一套 CRUD/发布接口。新资料纳入账号导出、注销和隔离测试，使用现有账本授权，不恢复首页授权按钮，也不增加第二套授权系统。

无论是否新增案卷，当前 `view_ledger` 最多 100 笔，**不能让模型用抽样流水自行推算整月总额**。Story 与洞察优先复用现有服务端汇总和 Agent 依据；只有现有路径不能满足已验证需求时，才评估最小只读汇总/背景契约，复用共享计算与服务端授权。

### 4.2 账房：一张主图、一份账册

默认先回答“选定期间，收支如何构成”。顶部用一行紧凑金额摘要替代三个独立指标卡；下方是主图与交易索引。

- 收入/净支出对照：对齐的横向条形，准确标注单位；转账独立，不混入消费。
- 分类支出：排序条形图，点击类别联动现有分类筛选，避免首页巨型甜甜圈和另一份重复分类列表。
- 时间变化：在数据接口支持时用按日/周折线或条形切换；新增聚合须进入后端共享服务，不能对当前分页的 25 笔当作全量统计。
- 交易明细：保留表格进行核对与批量操作，默认折叠次要列，手机按日期分组展示。编辑、删除、撤销、家庭共担与内部往来标记继续可达。
- “记一笔 / 导入 / 待审核”作为账册工具栏操作。导入打开同空间的任务面板，展示预览、映射、确认、队列与失败信息。关闭面板不应让正在运行任务失去可见入口。
- AI 辅助分类放在待审核页签，展示建议、置信度、依据、选择应用和撤销；不在每次查账时占据大块页面。

### 4.3 钱庄：财富结构与数据可信度同等重要

采用资产与负债两侧对照条形、同轴金额及净资产结论；账户按现金、非现金资产、负债组织。支持点击图中分类定位到账户。单一资产、零负债等情况有明确空态，不制造假切片。

仅在服务端确认覆盖完整且估值有效时显示精确净资产。覆盖不足时主要位置展示“已记录的资产/负债范围”和缺失原因，不将已录入部分标为全部财富，也不使用收入减支出替代净资产。

账户更新采用快照编辑抽屉，保留共有代号、归属、是否现金账户、是否纳入家庭、归档和有效期管理。资产趋势只在有真实历史快照、聚合口径明确时展示；不能从当前余额绘制虚构历史曲线。

### 4.4 集市：比较选择，不堆预测卡片

左侧紧凑条件：方案名、下月消费日期、额外金额、保留目标、保护类别；主要操作为“运行模拟”。模拟结果出现后，条件不消失，用户可调整并比较。

右侧一张前后时间轴，突出发生计划消费的日期和差值；预测区间折叠进图例与覆盖层。下方仅展示可行性、需要调整的金额/约束及周期账单。保存方案位于结果标题附近，已有方案进入选择器而非长期占用整栏。

保留现有下月自然月范围、优化约束、AI 复核状态与失败时的本地结果、来源交易下钻。没有可信起点时将时间轴标为“累计净现金流变化”；当前 `ScenarioComparison` 与 `Outlook` 的余额措辞须核对服务端数据条件后修正，不为美术效果牺牲口径。

## 5. AI：Story 中的主动分析师与按需助手

主动分析师复用 Agent 事实、规则与简报，在 Story 中组织变化、可能解释、证据与可选行动；因果不明就标记待核实，不把一次异常直接归因为用户的生活行为。事实叙事无需 AI 也能完成，已授权 AI 洞察按现有频次与缓存补充，失败只影响相应段落。

被动助手复用 `AiChat` 的消息、历史、思考折叠、错误恢复、流式进度和停止功能，按需展开会话；村庄默认以轻量入口和段落内追问承接，不挂载两份会话。主动分析师与被动助手共享事实范围，但不是两套权限或必须两次调用模型。

- 村庄首页：先看 Story，“富贵村财务管理助手”随时可展开；关闭后返回原阅读位置，不清空对话。
- 打开建筑：保留同一个会话与上下文；按需展开/收起。不要因路由淡入淡出而卸载正在流式输出的会话。
- 从 Story 追问：附带月份、章节主题、选中类别/图表范围、建筑与可用事实版本，输入区显示可移除的上下文标签；这些是可校验的范围提示，不是前端声称的授权或权威金额。
- 首期优先利用现有消息/工具筛选传递上述语义，不增加一套上下文数据库；若确需结构化请求字段，再做最小契约扩展、类型生成与后端校验。后端重新读取本人事实，不信任前端提交的汇总数字或任意对象 ID。
- 当用户切换月份、空间或选中项时，显示当前上下文范围；不把更新后的上下文倒灌进已发出的请求。账号切换清除旧范围，家庭数据范围仍以现有服务能力为界。
- 从盘点提问：首期只包含用户主动提交的本次说明；后续若有持久化档案，再由服务端读取并校验 ID、版本与有效期。不要静默上传草稿。
- 从图表提问：通过明确操作传递所选范围/类别，输入框显示可移除的范围标签，禁止悄悄扩大到家庭私账。
- 财务数字使用服务端事实；模型的推断与用户说明有来源标注。需要证据时可回到账房的相关记录。
- 家庭模式：保持当前个人 AI 不读取家庭其他成员私账的边界；不能因为看见同一村庄就自动扩大 AI 资料范围。
- AI Key 设置与状态复用现有连接组件和后端加密存储，前端不接触密钥解密。

### 5.1 跨建筑行动链

下钻应传递明确业务范围，不只打开建筑首页。复用已有筛选路由、图表回调与方案输入；模拟的金额/条件仍需用户确认，不从一句模型建议静默提交。

| 起点 | 目标与上下文 | 返回行为 |
| --- | --- | --- |
| Story/洞察中的异常消费 | 账房，带日期、分类或已校验的交易 IDs | 返回原 Story 位置与高亮 |
| Story 消费类别/集市节点 | 账房中同期间同类别交易 | 保留来源类别，允许清除筛选 |
| 账房类别或交易选择 | 集市，带来源范围，预填相关条件并请用户确认 | 保留原账册筛选与选择，不把历史消费重复作为计划入账 |
| 钱庄覆盖不足 | 账户编辑/覆盖确认，定位缺失或过期项目 | 更新后同时刷新钱庄与 Story 状态 |
| Story 的预算偏差 | 商会大厅/已有预算编辑；需要比较消费时转集市 | 保存后使相关事实与洞察失效重算 |
| AI 行动建议 | 经允许的站内目标及合法筛选；先展示“查看记录/比较方案”等按钮 | 保留当前对话和来源段落 |

行动使用前端允许列表映射到真实路由与组件；模型不能返回任意可执行 URL、修改权限或绕过确认。复用同一套跨区跳转与返回状态，不为每座建筑单独维护一套孤立导航。

## 8. 视觉规则：手绘场景中的现代工具

### 8.1 材质与层级

- 美术基准明确分工：《部落冲突》仅参考中世纪商贸建筑的造型、比例与色彩；《旅行青蛙》参考二维手绘描边、平涂上色与绘本质感。视频作为现有底图；后续新增图标、建筑高亮和补充图形服从这套方向，不回到低多边形 3D、写实渲染或泛化日系 RPG 概念图。
- UI 保持现代、简洁、商务。Story 的视觉层级来自叙事重点、数字与关系的编排，不靠章节都变成游戏道具；建筑和环境承载世界观，表单与图表承载清晰操作。
- 主场景保留视频本来的石材、瓦顶、草地、蓝旗与水面色彩。交互面板以暖白、浅米、深青墨色响应这些色彩。
- 工作面板只在边缘加入细金属/木色强调，正文区干净；不铺大面积高频纸纹，不将每个按钮制作成厚重仿木牌。
- 对话面板采用细窄标题条、安静的助手标记、清晰输入与轻量消息分隔；商会大厅用文档章节、月份索引和编辑状态形成明显区别。
- 圆角按控件性质少量使用：输入/按钮约 6–8px、工作面板约 12px，具体以首轮视觉校准为准。形状不是创意主体；村庄场景与工作流才是。
- 颜色、材质、阴影、尺寸全部落入现有 CSS/Tailwind/图表令牌，页面不新增同义硬编码。图表硬编码色值、原 Card 外观需随迁移清理。

### 8.2 字体与文案

- 正文 14–16px、图表标注与次要信息至少 12px，按钮文字 14px；主要工作区标题 22–28px。主页不再用 60–100px 的宣传标题。
- 数字使用等宽数字，金额统一人民币与两位小数，日期明确时区；主次不靠过浅灰文字区分。
- 全站字体使用稳定的中英文系统回退，若增加定制字体则本地托管并做体积与授权核对。中国用户不能被外部字体请求阻塞。
- 统一“账房 / 收支账本”“钱庄 / 账户与财富”等双层称呼。按钮用“保存盘点”“运行模拟”“导入账单”等准确动词。

## 9. 动效、视频与性能

### 9.1 动效只承载反馈与空间关系

| 操作 | 动效目标 | 初始参数 |
| --- | --- | --- |
| Story 章节/选择变化 | 对应建筑、关系路径与少量标签响应，保留阅读与选择 | 约 180–280ms；不强制滚屏/切页 |
| 资金关系 | 同一数据范围内的方向和构成，静态数字可核对 | 仅当前关系低频运动；可暂停，速度不编码未知金额 |
| 建筑 hover / focus | 标牌显现、轻微抬升，明确可点击区域 | 120–180ms，位移不超过 4px |
| 进入建筑 | 标牌反馈后工作区从建筑一侧展开；地图弱化 | 260–360ms，transform/opacity |
| 返回村庄 | 工作区收回，焦点回到原建筑按钮 | 200–280ms |
| 切工作区页签 | 正文轻量替换，保留滚动与输入草稿 | 120–180ms |
| 保存与任务完成 | 状态文字、图标和有限强调 | 无循环大动画 |
| AI 流式回复 | 稳定消息区，用户上翻后不强制追滚 | 状态可读，停止即时响应 |

不对固定视频强加鼠标视角旋转，也不伪造能穿越建筑的 3D 相机；这会破坏手绘素材与热区对齐。资金关系使用独立叠加层，暂停景观视频时仍可选择关系；用户暂停全部动态后保留静态关系和数字。现代感来自反馈、焦点、转场与细节，而非给全部元素增加漂浮效果。

### 9.2 素材发布与降级

- 原始 MP4 保留为源素材；发布素材进入 `frontend/public/media/village/`（或现有静态资源约定目录），提供版本化文件名和 poster。不得引用开发机绝对路径。
- 制作 1080p/720p 等合适档位；通过实际浏览器验证编码、首帧与循环，第一轮目标是明显降低当前约 15.55 MB 传输体积且不牺牲画面焦点。编码/码率在实测后确定，不承诺任意视频必能压到某个固定体积。
- H.264 MP4 作为广泛兼容候选；可选 WebM 只在验证收益后增加。去除无用音轨，`muted playsInline`，有 poster；交互内容不等待 `canplaythrough`。
- 仅保留一个视频实例。打开覆盖性工作区、后台标签、页面不可见时暂停；回到村庄再恢复。不在图表、弹层后继续无意义解码。
- 减少动态效果模式、节流偏好、低性能或加载失败时显示 poster。自动播放失败有手动播放入口，不阻塞业务。
- 若首尾接缝明显，先以 poster 降级或编辑素材；只有测试清楚后才考虑交叉淡入，避免双视频同时解码成为默认负担。
- 前端 Nginx 验证静态视频 Content-Type、Range 请求与缓存；缓存只用于版本化公共媒体，不能误缓存 `/api` 账本或 SSE。

## 10. 路由、状态与实施结构

保留所有旧深链与筛选参数。`/overview` 进入 Story 与村庄，`/ledger`、`/accounts`、`/simulate` 在对应工作区渲染。商会大厅的回顾/规划先使用已有数据和设置路由的兼容入口；必要时新增前端路由，但不因此要求新增月度后台服务。`/family/*` 继续使用原后端权限。旧 `/ai?conversation=...` 应打开对应对话而不丢失参数；`/import` 与 `/settings#...` 提供迁移后的可定位行为。

建议新增的前端职责（名称为计划，不是承诺的已有文件）：

- `components/village/VillageScene`：视频、poster、暂停与可见性。
- `VillageNavigation` / `BuildingHotspot`：坐标映射、标签、键盘和地点菜单。
- `VillageShell`：Story、空间切换、按需助手与路由工作区布局；不承担财务计算。
- `StoryView` / Story 视图适配：将现有事实、证据与行动目标组织成可连续阅读的内容，不另写财务计算或新造独立事实存储。
- `FinancialSceneOverlay`：与视频同坐标系的建筑状态、资金关系与选中标签；由当前 Story/选择范围驱动，不独立取数。
- `BuildingWorkspace`：工作区标题、返回、大小和转场。
- 商会大厅页面组合：复用现有回顾/预算/目标/议事；`MonthlyReviewEditor` 仅在后续确需案卷持久化时增加。
- 为 `AiChat` 适配按需侧栏/展开模式，抽离需要跨路由保存的会话状态；先复用现有组件，避免复制整套聊天实现。

最小联动状态是：当前月份/权限范围、Story 段落、所选类别/图表对象、建筑和来源返回位置。由外壳协调，事实留在 React Query；场景只消费视图状态。用户阅读、主动点建筑和助手展开互不重置。此处不建设通用剧情引擎或全新状态管理平台。

查询仍通过 React Query 与客户端模块。首页加载 Story 必需的现有汇总、范围与适用的缓存洞察，重图表/完整预测进入建筑后再加载；不对每座建筑轮询，也不因滚动触发新模型调用。导入、编辑、快照、预算更新后，按依赖统一失效 Story、场景状态和对应业务查询；事实变化与旧洞察要有可见版本边界。

草稿按账号/家庭空间/月隔离，退出登录清理敏感本地草稿。切路由或月份前区分已自动保存与未保存；保存失败保留草稿并给出明确重试。不能以路由动画卸载组件而丢失提交中状态。

### 验收清单

1. **Story 与视觉**：首页形成可自由跳转的连续理解过程；每个结论有范围和依据，不是六卡/六步；章节和选择驱动建筑反馈；默认完整聊天不占主位；图表文字可读。
2. **导航**：场景点击、地点菜单、旧 URL、浏览器前进后退等价；弹层关闭恢复焦点；触屏无需 hover；200% 缩放与 390px 窄屏均可完成操作。

4. **AI**：主动洞察与追问复用本人事实及授权；章节/建筑/选中图表范围可见可移除；发送变停止、异常恢复草稿、历史 Markdown 一致、跨路由输出不中断；按既有频次复用/请求简报，不因滚动或高亮付费分析。
5. **账房**：新增/导入/审核/应用/撤销/删除/筛选/分页/详情/家庭标记保留；任务失败不伪装排队成功，原有部署故障遗留任务的恢复作为独立可靠性问题处理。
6. **钱庄**：资产负债和净资产口径正确；范围不足为未覆盖；过期/冲突不输出精确财富；快照历史不被覆盖。
7. **集市**：保护类别、自然月边界、零额、负值/超限拒绝、无可行方案、区间、来源与 AI 复核失败边界明确；保存不重复入账。

9. **家庭**：组长/成员视图、撤销共享、历史共享起点、邀请确认、退出转让、共有冲突与内部往来口径继续验证。
10. **公共组件**：在开发 `/components` 中补完整正常/加载/空/错误/禁用/焦点状态，保持页面不进入用户导航。

验证使用项目要求的格式、Lint、类型、前端构建与适用后端计算/授权测试。新增盘点契约须运行 Alembic 验证和 OpenAPI 客户端生成。Playwright 每次使用独立数据库、端口和测试账号，不使用真实账本或 API Key。截图可使用受控演示夹具，生产空态不填充演示金额。
