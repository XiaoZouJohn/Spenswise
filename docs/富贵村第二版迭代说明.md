# 富贵村第二版迭代说明

依据《富贵村第二版开发清单.docx》实施；升级前已将 `1116_lhq` 分支提交并推送，备份提交为 `eb6cb52`。

## 功能入口与实现

| 清单 | 实际入口与行为 |
| --- | --- |
| 01–06 首页 | 保留动态村庄与全局悬浮 AI。首页提供继续阅读和待办入口；四座建筑读取服务端状态。月份、章节与选中类别由同一场景状态维护，进入建筑保留 Story。 |
| 07–15 Story | 五章生活纪事：这个月、消费去向、值得留下、留下什么、下个月。可选择月份、继续阅读、跳过和直接处理；关键金额来自共享服务，每章提供来源下钻。 |
| 16–25 账房 `/ledger` | 导入、记一笔、待处理作为主要操作。新增未分类/待核对/近期导入异常提示、批量修正日期与账户、确认记录。详情折叠展示目的、感受和说明，可关联日志、打开相关故事或询问 AI。分类授权及撤销沿用原组件。 |
| 26–30 钱庄 `/accounts` | 保留现有资产和家庭覆盖口径。点击账户打开最新余额、真实快照历史及已关联流水；可更新快照或下钻交易。旧流水没有账户关联时不会猜测归属，收支差额不作为资产净值。 |
| 31–35 集市 `/simulate` | 新增消费回看与原有消费模拟两个入口。类别显示本月金额、占比、同口径上月及变化；抽屉区分账本记录、你的记录、分析判断。大额规则事件和主动标记事件可以补充背景、关联日志及稍后处理。 |
| 36–45 议事厅 `/review` | 改为自然问题：特别的事、下月最想做好的事、需要记住的补充。支持选择当月生活记录，显示修订号和保存时间；回到 Story 的下一步章节，保留草稿。 |
| 46–61 生活记录 `/logs` | 日期时间线、轻量编辑、私有可见、逐篇 AI 使用许可、多对多交易关联。无关联交易也能保存。删除清空正文但保留来源墓碑，历史故事和回顾显示已删除占位。消费背景可仅保存为事件说明，无需强制写日记。 |
| 62–73 AI 纪事与对话 | 用户主动整理纪事，服务端生成任务并保存五章版本、事实和来源。离开后可查任务，失败保留旧版本，账本更新提示过期。聊天增加只读生活记录工具，与原账本工具共用授权；日志需逐篇允许。模型不决定结构化金额。 |
| 74–89 场景与视觉 | 真实待办数量、完成状态与角色提示，沿用手绘图集、视频及局部建筑高亮；统一纸页、账簿行、来源、草稿与状态组件。沿用 Motion 转场，减少动态设置控制 UI 动效。季节资源表按日期选取，缺失时回退现有素材。 |
| 90–98 数据和恢复 | 新增日志、交易关联、消费事件、故事版本/章节和按资源隔离的草稿。草稿本窗口缓存加服务端版本控制，冲突拒绝覆盖；导入任务可从历史继续查看。账号导出及注销覆盖新增数据，延迟草稿同步校验预期账号。 |
| 99–105 响应式 | 桌面 Story 与工作区并排、各自滚动；窄屏用 Story/地点/工作区切换，移动端地点使用显式列表。抽屉沿用键盘、Esc、焦点管理。 |

## 数据与部署

- Alembic `0008` 在交易中增加可空账户关联与核对状态，并新增六张表。旧账单不自动关联账户，不改动原金额。
- 沿用现有 `compose.yaml`、API 启动迁移、PostgreSQL 数据卷、Redis 和 Celery。新增任务名 `spendwise.story`，部署需要同时更新 API 与 worker 镜像。
- API 客户端已重新生成。金额为整数分，退款冲减净支出，转账不计收支；历史比较按两个月共同可用的日期范围展示，比较结束日明确显示。
- 保留共用 AI 账本许可；生活记录默认不供模型读取。删除或撤销许可后，相关旧对话拒绝继续发送，生成纪事的相关正文隐藏并提示重新整理。
- 生产数据库升级前照常备份。此次未连接云服务器、未修改生产 `.env`、未将分支合并至 `main`。

## 已核对与仍需体验的部分

已核对日志、交易、回顾、草稿、任务的账号隔离和删除引用；后端 56 项检查通过，Ruff 格式/Lint、Mypy、前端类型、Lint、构建通过。浏览器使用独立数据库和 `18086/5178` 端口，截图在 [design-review/v2](design-review/v2/README.md)。没有使用真实用户账号或模型密钥。

真实 DeepSeek 输出质量及云端队列速度仍需部署后体验。四季视频/插画尚未提供，本轮仅实现资源接口及回退；建筑标记继续采用已有场景文字与状态，新的专用木牌、暖灯和角色动作素材可后续替换，不用 CSS 几何图案代替手绘素材。当前事件自动规则采用可解释的单笔 500 元门槛，同期类别变化在消费回看展示，不将它冒充统计异常检测。

迁移核对：独立数据库可升至 `0008`。`alembic check` 对新增表没有报告差异，但会报告既有 `users.email` 索引的模型/历史迁移表达差异；本轮未顺带改动既有身份表。
