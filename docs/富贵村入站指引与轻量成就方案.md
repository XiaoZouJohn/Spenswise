## 本轮视觉参考的取舍

两张参考图明确了方向：欢迎纸页叠在村庄场景上、锚定 Story 操作的气泡提示、藏书票式纪念册、移动端底部纸页。采用其中的**布局、纸张质感、森林绿主色、暖金细节和小猫叙事**，不把整张参考图作为页面背景，也不在每个组件周围重复厚重卷轴边框。标题层级以本地 Noto Serif SC、普通界面以 Noto Sans SC 为主，数字沿用 Lora；继续使用现有设计令牌，必要时在 `styles.css` 增补少量纸张与金边令牌，避免各组件散写近似色。

参考图含有旧文案“本月生活纪事”“整理本月纪事”和另一套五步名称；**实际产品保留最近已确定的“本月财务回顾”“生成本月回顾”及当前五阶段文案**，不借这次入站指引改写 Story 接口、章节顺序或正文。图中“连续记账 7 天”“本月有结余”也只作为徽章排版示意，首版不按这两个条件授予：前者会制造打卡压力，后者容易把收支差额误当财富结果。

## 目标与依据

新用户应在几分钟内知道“数据从哪里来、Story 能看什么、AI 何时有用”，而不是先记住四座建筑的全部功能。完整的强制教程容易打断任务且常被跳过；在用户真正进入功能时给提示，并允许以后重看，更适合当前村庄界面。[NN/g 对教程与情境帮助的研究](https://www.nngroup.com/articles/onboarding-tutorials/)、[NN/g 对移动端引导的分析](https://www.nngroup.com/articles/mobile-app-onboarding/)

成就用于肯定“完成一次有意义的财务整理”。个人财务应用的研究发现，游戏化与自主感、胜任感及使用意愿有关，但这不能证明单放徽章就会让 SpendWise 用户持续使用。[个人财务管理应用研究](https://selfdeterminationtheory.org/wp-content/uploads/2024/03/2021_BitrianBuilCatalan_IJBM.pdf)、[徽章实地实验](https://gamification-research.org/2013/05/1-5-year-experiment-on-gamification-surprising-results/)。金融场景还应避免把奖励绑定到更多交易或更高金额；交易应用实验发现某些游戏化机制会增加交易频率和风险行为，虽然它研究的是投资交易，不能直接推断记账产品的效果。[FCA 实验](https://www.fca.org.uk/publications/fca-research/research-note-digital-engagement-practices-trading-apps-experiment)

## 一、入站指引

采用**一张欢迎纸页 + 三次情境提示**。首次注册后进入 `/overview` 时展示欢迎纸页；登录老账号、已有账单的用户只在个人资料中看到“重看使用指引”入口，不自动弹出。每一步都可“稍后再说”，不挡建筑热点、Story 滚动和 AI 浮窗。引导不能成为导入账单或使用 AI 的前置条件。欢迎纸页不计入后续提示的 `1/3` 进度；成就获得反馈是另一种状态，不混入教程步数。

| 时机 | 小猫说什么、用户能做什么 | 落点与完成判定 |
| --- | --- | --- |
| 1. 初到村庄 | “先从一笔真实记录开始。”提供“导入账单”“手记一笔”“先看看村庄”三个清晰入口；选第三项立即结束欢迎纸页。 | 挂在 `VillageShell` 的场景交互层；导入按钮复用现有 `/ledger?import=1`，手记按钮需要给 `Ledger` 增加 `?new=1` 深链并打开现有新增抽屉，第三项关闭纸页。第一步只记录用户选择，不冒充已记账。 |
| 2. 到账房后 | 在空账本或首次打开导入界面时给一句提示：可先预览、确认后才写入；已有账单则不再提示。 | 复用 `Ledger`、`ImportPanel` 的现有空状态与任务状态。以本人首笔已保存交易，或导入任务实际新增至少一笔为完成，不把上传或预览算完成。 |
| 3. 回到 Story | 首次有账单时，先在标题附近提示“这里从账目读出本月情况”；用户看到月份选择或“生成本月回顾”时，再把小气泡锚定到该控件。另一次提示放在五阶段导航旁，说明可以自由切换。没有 AI 连接时先展示账本事实，按钮可引导至现有连接设置，不自动请求模型。 | `StoryPanel` 读取已有交易数与纪事版本状态。气泡只在目标控件可见、位置测量成功时出现；用户可以直接阅读或主动生成，不要求先写生活记录或逐笔备注。 |
| 4. 需要解释时 | 用户第一次主动展开悬浮小猫，再说明可提问、可跳到账房/议事厅，AI 只按现有授权读取数据；提示在输入区附近，不覆盖聊天内容。 | 复用 `AiLauncher` / `AiChatWindow`，不另建对话入口、密钥或授权系统。 |

前两步是真实操作路径；后两步是功能发现。用户从任何深链进入时直接显示目标页面，不强行送回首页。引导状态按 `owner_id` 保存“已看/跳过/已完成”的版本号；账单保存、纪事生成等事实由服务端核对，不能由前端写一个 `completed=true` 伪造。可复用现有用户隔离的 `Setting` 存储引导进度，首版不增加表；新增专用读写 API 时仍走当前会话身份校验。多设备同步以服务端为准，浏览器只缓存尚未提交的当前步骤。

## 二、轻量成就：村庄纪念册

入口放在 `/user` 的“村庄纪念册”，版式参考图中的横向集章卡：左侧册封插画，右侧展示已获得、未获得和获得日期；未获得的章可点开看真实条件，但不展示带压力的倒计时。首次获得时只在当前任务完成处短暂出现一张小型藏书票，并提供“查看纪念册”。不在首页增加常驻积分面板，不设等级、排行榜、连续登录天数、消费金额目标或失败惩罚。纪念章用手绘书签、印章、纸角等位图装饰，UI 文本仍保持现代清晰。

| 纪念名 | 服务端可核实条件 | 对应业务与反馈 |
| --- | --- | --- |
| 第一页账簿 | 本人首次保存一笔交易，或导入任务完成且 `inserted > 0`。 | 账房保存或导入结果出现一次“账簿开篇”；重复导入、仅上传文件不授予。 |
| 留下一件事 | 本人首次保存一篇未删除的生活记录。 | 议事厅生活记录页出现藏书票；记录可以不关联账单。 |
| 一次认真回看 | 本人首次保存有效月度回顾，`monthly_review:{month}` 存在 `saved_at`。 | 议事厅保存后出现纪念章；查看或保存空草稿不算。 |
| 写成本月故事 | 本人首次有 `StoryEdition.status=completed` 的纪事。 | Story 生成成功后出现纪念章；排队中或失败不算。无 AI Key 的用户仍可获得其他纪念。 |

首版可由现有用户归属数据**按需计算获得状态和最早日期**，不新增成就表或 Celery 任务；查询结果只返回当前账号的成就 ID、获得时间和可打开的业务入口，不暴露金额、账单正文、家庭成员数据。若原始记录被删除或回顾被清除，按当前证据重新计算，纪念可以消失；界面需对此给出中性说明。将来若希望“删除原始内容后仍保留纪念”，再讨论独立、可撤销的授予记录和迁移。账号注销时随账号数据清除，家庭成就暂不做，避免权限与共享口径混淆。

## 实施顺序与验收

1. **视觉小样**：用 `pic/` 四张现成姿势做欢迎纸页、账房/Story 气泡、纪念册及 390px 手机底部纸页原型；先清理“思考”图边缘。核对纸页在视频每一帧上是否可读、气泡是否指向实际控件、小猫是否保持同一比例。
2. **指引首版**：增加账号隔离进度 API 与 `Setting` 存储；在现有组件挂载提示，保留跳过、稍后再说、重看和深链直达。前端请求继续走项目 API 客户端。
3. **纪念册首版**：服务层读取四项里程碑，API 返回最小结果；`UserCenter` 组合纪念册组件，业务操作成功后刷新成就查询。一次操作最多出现一次授予反馈。
4. **体验验证**：找少量从未用过 SpendWise 的同学，分别完成“导入或手记一笔”“找到本月收入”“向小猫提一个账目问题”；记录是否需要提示、是否跳过、是否能自己回到任务。对比有无引导时的完成率和所需时间；成就只看是否提升主动回顾与理解，不以点击次数或记账笔数为成功指标。

开发验收重点：新老账号及跨设备状态隔离；导入重复/失败不误授予；注销清除状态；无 AI Key、无账单、被删除记录都能得到准确文案；键盘可操作、关闭后焦点返回、减少动态效果生效。正式开发时同步更新 `FEATURE_PARITY.md`，按现有独立数据库与端口规则验证，不使用真实账号或 API Key。
