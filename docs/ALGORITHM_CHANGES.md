## 使用入口

1. 在“预算与设置 → 历史记录覆盖”添加**确实完整记录**的时间段；不要把未知或未导入的月份确认成完整。
2. “消费模拟 → 余额与确认收支”可填日终余额快照、未来确认收入和额外支出。额外支出不能重复填写日常消费、周期账单或主输入框中的购买金额。
3. “分类削减偏好”设最低保留、削减比例和权重。未设置分类默认上限 40%；保护分类始终不可削减。
4. 运行后查看支出构成、逐日结果和“执行削减后”曲线。输入变化会清除旧结果；查看已保存方案同时恢复当时的输入。

现金流以每日结束时的金额计算，不模拟日内先后顺序。没有快照时目标也是净现金流目标；有快照才可解读为最低余额目标。快照之后的账本若不完整，页面会提示余额推算可能遗漏交易。

## 回测命令

在 `backend` 下，使用项目 Python 3.12 环境：

```powershell
python -m scripts.backtest_forecast --input ../sample-data/forecast-backtest-demo.json --owner-id 1 --as-of 2026-10-31 --output backtest-result.json
```

输入结构见示例文件。`transactions` 必须含用户归属与日期等列；`coverage` 仅描述命令指定用户。命令只读取输入文件，不连接数据库或 AI。回测自动过滤其他用户及截至日期之后的记录。

指标包括 MAE、偏差、区间覆盖率及平均宽度；两个点预测基线的区间宽度设为零，不应把其覆盖率当成概率区间校准结果。默认最后两个可评估月份留出，模型仅由此前验证月份选定。留出阶段仍逐月滚动，前一个留出月已发生的交易可用于后一个月训练，模型选择不再更改。回测报告不会自动更改线上模型。

附带的是**合成例子**：固定房租加恒定每日消费。2026-03 至 08 为验证月，09 至 10 为留出月。留出 MAE：上月值 1000 分、三月均值 500 分、旧集成 489.5 分、分解模型 0 分。该数据专门检验固定账单与月份天数的拆分，不能用于宣称真实用户准确率提升；还需用完整、脱敏的真实历史做独立评估。

## 当前限制与后续工作

- 历史覆盖仍依赖用户确认；无法从一条交易反推出账本完整。
- 周期识别为保守月度规则；并非自动知道订阅取消、金额变更、季度/年度扣款。实际到期金额不确定时应复核。
- 支出范围是历史偏差范围，尚未基于足够真实滚动残差校准为概率置信区间。
- 整数求解设有时间上限；未找到可行解时返回未解决缺口，不伪造可执行建议。未提供“最大程度缓解但仍失败”的部分削减方案。
- 固定/可变预测目前是明确、可测试的默认模型。真实数据回测若不支持其效果，应据验证集调整，而不是反复查看留出集后调参。
- 本轮没有修改自动分类、异常检测、导入去重，也没有部署 Qwen 或本地大模型。

团队合并前需另一成员审阅共享契约与计算变更；最后一处手机图例显示仍需浏览器复验。
